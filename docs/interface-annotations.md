# Interface annotations

Open a web page, local app preview, or HTML file in **Stage**, then choose the **Annotate** dashed-square pointer icon in the address toolbar (the same icon as Engelbart Web). Hovering or focusing the control shows its name. Selection starts directly, without a sidebar or any change to the page width. The icon has a quiet active background and the hover label **Annotating · Esc to cancel**. Hovering an element shows a pointer cursor and a thin neutral outline, without a floating label box. Escape or the toolbar action exits selection and removes its overlays and temporary cursor override.

Click an element to freeze the selection and open a compact contextual composer. The click is intercepted before the page's controls activate. Write in one text box, then use **Cancel** at the bottom left or **Add note** and the primary **Ask Bart** action grouped at the bottom right. Ask Bart sends the text, together with the page and selected element's context, to the existing Bart conversation in the workspace document; it does not implicitly create a saved annotation. Add note saves the text directly as an annotation, without sending it to Bart or requiring a second Save button. ⌘/Ctrl+Enter defaults to Ask Bart (or saves a note if Bart is unavailable). Sending, saving, Cancel, or Escape closes the composer, clears the selection, and restores normal page interaction. Handoff errors leave the draft in place. The composer uses Stage's existing overlay/snapshot mechanism, so the page stays the same size and the selected element remains visible behind it; the underlying native page is temporarily covered by its snapshot while writing.

Choose **More (⋮) → Annotations** to open a compact floating list over the current website, without narrowing or shifting the page. Each row leads with the note text, with its website or repository name underneath. The heading has no count; row numbers still match their page markers. The list and saved-note popovers are at most 300px wide and 420px tall, scrolling internally when needed. Clicking a note locates and highlights its element, then replaces the list with a contextual note popover beside the target. Clicking a numbered marker opens that same popover. **‹ Annotations** returns to the list; Close, Escape, or clicking outside dismisses it. Editing, deleting, **Ask Bart**, and **Open page** still use the existing actions. New notes are created through the toolbar's **Annotate** action, not from a sidebar.

The collection follows the active Stage tab, including its other routes; unrelated websites are excluded. There is no separate Notes shortcut in the address toolbar. A blank Stage asks you to open a website. An offline preview URL still identifies its saved notes. Notes whose targets are missing or on another route remain readable in the floating popover, with the existing matching feedback and **Open page** action when available. Only the current site's anchors are sent to the page. Dismissal removes the overlays and listeners without reloading the page. As with the composer, browsing uses Stage's existing snapshot overlay; the underlying page retains its full viewport while the popover is open.


Notes belong to a project and site, and each saved note has a library ID. Saving on an unsaved website creates a local library entry; existing sites are reused. Sandbox captures link to the repository, not a separate entry for each preview. Preview-origin aliases persist in the local library database, including before a resumed run clears its old URL. Notes remain readable during rebuilds and link to the latest ready preview afterward. Original capture URLs remain as provenance. Local HTML files use their file URL. Credentials and query strings are not stored. PDF ink continues to use its existing independent format.

On startup, existing annotation files are adopted without changing their IDs, text, or anchors. The original project/scope hash verifies ownership before migration; historical run IDs recover repo associations even if the old hostname has already been replaced. All note data stays local.

## Implementation

- `src/main/browser/annotation-page.cjs`: DOM picker, overlays, same-origin child frames, open shadow roots, and target recognition. The main process installs this script on demand with `executeJavaScriptInIsolatedWorld` (world 1739). Canvas does not modify the server's HTML response.
- `src/main/browser/annotations.cjs`: per-tab controller. Only the trusted app renderer can invoke its small command vocabulary. Main polls the isolated context while annotating or browsing saved notes. Pick, marker-click and locate results include bounded, temporary viewport coordinates for popover placement; those coordinates are not saved in the anchor. Website scripts receive no IPC API, note text, filesystem capability, or annotation message listener. Navigation and tab closure invalidate pending results and stop polling.
- `src/shared/interface-annotations.cjs`: bounded, allowlisted anchors and note validation, plus the shared display label used by the composer and saved-notes list. Text-entry values and contenteditable contents are excluded from captured element descriptions.
- `src/main/store/interface-annotations.cjs`: atomic per-record mutations to `<dataRoot>/annotations/interface/<hash>.json`. Keys include project ID and repository/site identity. Storage failures remain visible in the editor. Concurrent additions do not replace one another.
- `src/main/store/captured-sites.cjs`: shared local source resolution for notes and recordings, automatic website registration, and durable repo-preview aliases. Website tags alone never turn an ordinary webpage capture into a sandbox capture.
- `src/renderer/workspace/InterfaceAnnotations.jsx`: the existing editor, saved-notes list and note details share the viewport-clamped `StagePopover.jsx` shell with the recordings list. Markers appear only while using annotations; closing clears them. Direct selection renders nothing until a target is picked. Browsing and reading notes no longer allocate a sidebar or resize Stage. `Stage.jsx` and `views.cjs` refresh the backing snapshot after locating a saved target, including when an open list has already hidden the native view.

Matching tries a unique test ID, element ID, and selector (including open shadow-root hops), followed by a unique best candidate using tag, role, text, classes, and ancestors. The UI distinguishes **found**, **closest match**, and **not found**. Screen coordinates never determine identity. Markers update as the page changes or scrolls.

The bridge checks installation inside the current page's isolated world for every non-cleanup command, using the idempotent picker installer. Cleanup is a no-op when that helper has disappeared and never installs it just to clear it. Execution failures from a superseded document or destroyed tab are treated as cancellation; genuine errors in the current document still propagate. Regression tests cover absent/lost helpers, reinstalling on actions and polling, and navigation/cleanup/disposal races. The Electron smoke test also exercises missing-helper cleanup and recovery through the actual IPC handler before testing a real page reload.

Cross-origin or opaque sandboxed frames cannot be inspected internally; their iframe element can be selected instead. Closed shadow roots and graphics within a canvas are represented by their host element. A DOM anchor does not automatically identify a framework component or source line. URL query parameters are deliberately excluded from page identity.

## Verification

```sh
npm run build
node --test test/captured-sites.test.cjs test/interface-annotations.test.cjs test/interface-annotations-ui.test.cjs test/browser.test.cjs test/library.test.cjs test/stage-model.test.cjs test/right-pane.test.cjs
node_modules/electron/dist/Electron.app/Contents/MacOS/Electron scripts/smoke-interface-annotations.cjs
```

The Electron smoke test uses a disposable home and a loopback fixture with strict CSP, nested frames, and a private input. It opens a temporary window without taking keyboard focus and exits afterward. It exercises full-width selection and browsing, neutral semantic hover, pointer restoration, Escape from the page and toolbar, contextual composing and saved-note popovers, list/back/outside-click interactions, refreshed snapshots after locating a target, the actual Stage controls, persistence, matching, frame selection, Ask Bart, deletion, and cleanup. The final output reports screenshots and the disposable data directory.

It also checks unsaved-site registration, cross-site marker isolation, blank-Stage discovery after a renderer restart, and reopening the saved website. The marker toggle is exercised through Save, Close, Delete, Escape, reload, route/tab/site changes, and preference restoration; normal page clicks and full-width layout are checked with pins enabled. Run the same script with `--restore <reported-root>` to reopen that fixture in a completely new Electron process and verify the library links, notes, restored marker and remembered visibility preference. Store tests close/reopen the database, migrate legacy files, and exercise a same-run rebuild that clears and replaces its preview URL.
