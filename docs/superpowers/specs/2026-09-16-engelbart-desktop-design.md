# Engelbart desktop (experiment branch) — design spec

Date: 2026-09-16. Status: implemented from this spec without an approval gate (autonomous session); every interpretation is listed in §2 so it can be overridden.

## 1. What this is

A macOS desktop app named **Engelbart**, installed like Experimental Terminal (an unsigned Electron `.app` under `release/`). It is a **simulation / testing environment** for the *Goal Canvas* design (`design/goal-canvas/Goal Canvas.dc.html`, plus the 33 tweak messages in `design/goal-canvas/USER-TWEAKS.md`). Nothing is wired to a model. The point is to iron out storage, representation and interaction details before agents are attached, and to be usable for planning in the meantime.

Out of scope now: live preview, dataset viewer (both render the word *placeholder*), any LLM call, document import/upload, sync, auth.

| 40 | Summaries | The library table gains `summary` (default null), `summary_edited`, and `char_count` (notes only, written with every save, so it follows typing at the editor's 400 ms save beat). While the app is open the harness sweeps the table once a minute, again at launch and when the computer wakes; a continuous loop would buy nothing, since every condition is about half-hours. A note is dispatched when it has not been edited for 30 minutes and either (1) its summary is null: file + system prompt in, summary out; or (2) its summary is older than its last edit: file + system prompt + current summary in, summary out. Both write `summary` and `summary_edited` and nothing else. First the file must be longer than 1,000 characters; a shorter note keeps a null summary, and one that shrank loses its summary. Images and every other non-PDF type stay null. The system prompt is `src/main/context/summary-prompt.cjs`; a file at `<dataRoot>/.context/summary-system-prompt.md` replaces it without a rebuild. ## 6. Data model (SQL, Postgres dialect via PGlite)

```sql
-- root: library.pglite
create table if not exists library (
  id uuid primary key,
  name text not null,
  type text not null check (type in ('md','pdf','html','csv','tsv','json','jsonl','parquet','xlsx','folder','website','image')),  -- what it is (§2 #61)
  tags text[] not null default '{}',  -- what was inferred: paper, git, note (note only on an md)
  categorized integer,                -- version of the category rules applied (library.cjs CATEGORY_RULES); null = none yet
  path text, url text, folder_path text,
  project_id uuid,
  created timestamptz not null default now(),
  last_edited timestamptz not null default now()
);
-- per project: notes.pglite
create table if not exists notes (
  id uuid primary key,
  name text not null,
  path text not null,            -- relative to the project directory
  goal_id uuid, topic_id uuid,   -- addition, see §2 #6
  created timestamptz not null default now(),
  last_edited timestamptz not null default now()
);
```

A note is one row in both tables (same id); `library.path` is absolute, `notes.path` relative.

## 9. Known kinks (left open on purpose)

1. The normal root (test off) has no seeds and no ingestion path yet, so its library only ever holds notes.
2. Library ingestion beyond seeds (register a downloaded PDF by path? watch a folder?).
3. Whether goals/topics also want SQL rows (they are directories + `meta.json` now).
4. Deleting anything; archiving Past goals; moving a goal between boxes.
5. Note↔goal association lives in the notes table, not in the file. Obsidian would use frontmatter properties.
6. Todo build statuses and chat replies are simulated; nothing records them.
7. Images in documents.
8. Multiple windows / one project open at a time.
9. Without the canvas, a goal's box (Current / Experimental / Past) is only a label in the goal menu: new goals land in Current and nothing moves them.
10. The browser pane (decision 48): Google sign-in is rejected and passkeys are unavailable (decision 49); DRM video and client certificates are not handled; device presets change the width only (no mobile user agent or touch emulation); file and sandbox addresses are not part of the page history (← from one returns to the page underneath). Sandboxes are not connected.
11. The chat-style terminal: no Tab completion in the box; text typed during the first 200 ms of a command stays in the box; prompt hiding and the idle/running marks are zsh-only, and a prompt framework that rewrites `PROMPT` from a `zle` widget rather than `precmd` could still draw one. A shell you `exec` or nest by hand (`bash`, `ssh`) counts as a running program until it exits.
12. Images: no drag-and-drop, no resize, no deletion of an asset when its line is removed; an agent reading the markdown sees `img:<id>`, not a path (the file is `<project>/assets/<id>.<ext>`). Earlier sections of this spec (§3 layout, §5 Rail, decisions 8, 10, 11, 21, 23, 31) describe goals, topics and folders; decisions 34–36 supersede them.
13. Summaries: the catalog lives in the project's data folder, and nothing yet tells an agent started in the code directory where it is; the table does not record whether a summary is an abstract or a model's; Codex reports tokens but no price, so `status.json` has cost only for Claude Code; whether a blurb helps retrieval more than it hides notes is untested (compare retrieval from blurbs against full text on real messages before trusting it).
14. Selecting across a rendered line and deleting keeps that line's type (todo, heading) but loses inline markup the rendered view did not show (bold, links).
- **@bart (2026-09-19).** Codex's read-only sandbox can read the whole disk and has web search: private files and an outbound channel in one agent, with nothing to narrow it (Claude Code is confined). An answer is placed by the renderer, so leaving the project or reloading the window mid-run drops it (the pending line then offers Hide) while the run itself finishes unseen. Undo after an answer arrives restores the pending line, which reads as interrupted. The answer arrives whole, not streamed. No per-question cost is shown. Whether moving up is used well (too eagerly, never) is unmeasured: the attribution line on each answer is the data for that. Recognised flags are not highlighted on the line; the pending row shows which model was picked.
