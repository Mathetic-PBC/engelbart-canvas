Package `mac/Packages/Sandbox` (module `EngelbartSandbox`). Sources: `src/main/sandbox/**`, `src/main/github/e2b-key.cjs`,
`src/shared/sandbox-sleep.cjs`, `src/shared/environment.cjs`, sandbox handlers in `src/main/ipc.cjs`/`index.cjs`/`preload.cjs`,
`src/renderer/ui/SandboxProgress.jsx`, `SandboxNotifications.jsx`, `sandbox-notifications.css`,
`src/renderer/model/sandbox-notifications.js`, `src/renderer/workspace/EnvironmentPanel.jsx`, `environment-panel.css`,
`docs/sandbox-runs.md`. Tests: `test/sandbox-*.test.cjs`, `environment-report`, `github-e2b-key`.

Mapping decisions (Electron mechanics → Swift):
- **Worker process → in-process runtime.** Electron forked `worker.cjs` (ELECTRON_RUN_AS_NODE) per command so the E2B SDK
  and its key stayed out of the main process; Swift runs the same `WorkerRuntime` as a Task behind the same
  `launch(request, env, onEvent) → { done, detach, stop }` shape (`Transport.swift`). The request/ack/stop/detach
  protocol, event validation and the redaction at the boundary are kept; fork/IPC/EPIPE/asar mechanics are n/a.
- **E2B JS SDK → `E2BHTTPClient`** (URLSession): REST `api.<domain>` (`X-API-KEY`) and envd Connect-RPC (JSON codec,
  `application/connect+json` envelopes for server streams) at `https://sandbox.<domain>` with `E2b-Sandbox-Id` /
  `E2b-Sandbox-Port: 49983` / `X-Access-Token`. Only the calls Engelbart makes. Tests run it against an in-process
  `URLProtocol` fake; no real sandbox is created.
- **safeStorage → Keychain.** One AES-256-GCM key, generic password item service `Engelbart Swift Safe Storage`,
  account `sandbox-environments`; the `sandbox_environments.encrypted` column keeps base64 ciphertext as before. A row
  copied from Electron (encrypted with Electron's own key) cannot be opened: it answers "Saved environment could not be
  unlocked. Check your system keychain." and the person saves the values again.
- **PGlite SQL → `SandboxDatabase` protocol** (SQLite statements, executed by the Store's connection; the package ships
  `SQLiteSandboxDatabase` for tests and as the default adapter). The run log's 300-entry trim, `seq`, milestones and the
  agent activity tail are computed in Swift inside one write transaction instead of one Postgres UPDATE.
- **local-mcp.cjs → `<Engelbart> --mcp sandbox-local <connection.json>`** (Core.MCPServer). Image content
  (`mcpContent`, used only by Connect's browser tool) does not pass through Core.MCPServer (text only); the sandbox
  tools never answer with images.
- **Renderer localStorage → `NotificationStore`** (UserDefaults, key `engelbart:preview-notifications:<root>`); the
  cross-window `storage` event → `EventHub` event `sandbox-notifications:saved`.
